# Contract: protocol codec library (`proto` ↔ `core`, `client`)

**Status**: frozen at plan time (constitution 3.3). **Materialized** in the Foundational phase as
`contract/copy/PROTO.cpy` (buffer and value records) and the wire fixtures in `contract/fixtures/wire/`.

`proto` is a COBOL library of encoders and decoders for the data types of `docs/protocol/00-data-types.md`,
framing and compression (01 §2, §3), network NBT (07 §1 to §3) and chunk payloads (06). It has no knowledge
of game rules or connection phases. Both the server side (`core`) and the client side (`client`) of the
protocol build and parse packets with it.

## 1. Records (`PROTO.cpy`)

```cobol
01 PB-BUFFER.                       *> growable byte buffer
   05 PB-ADDR        USAGE POINTER.
   05 PB-CAPACITY    BINARY-LONG.
   05 PB-LENGTH      BINARY-LONG.   *> bytes written
   05 PB-POS         BINARY-LONG.   *> read position (0-based)
   05 PB-ERROR       PIC 9.         *> 1 after a read past PB-LENGTH or a malformed value
```

Reads never move `PB-POS` past `PB-LENGTH`; a short or malformed read sets `PB-ERROR` (the caller applies the
disconnect behaviour the protocol defines, 01).

## 2. Entry points

| Group | Programs |
|---|---|
| Buffer | `PB-INIT` (capacity), `PB-FREE`, `PB-RESET`, `PB-APPEND-BYTES` |
| Scalars (00 §1 to §6) | `PB-PUT-` / `PB-GET-`: `BOOL`, `BYTE`, `UBYTE`, `SHORT`, `USHORT`, `INT`, `LONG`, `FLOAT`, `DOUBLE`, `VARINT`, `VARLONG`, `STRING` (with max length), `IDENTIFIER`, `UUID`, `POSITION`, `ANGLE`, `LPVEC3`, `BITSET`, `FIXED-BITSET` |
| Composite (00 §7 to §12) | `PB-PUT-` / `PB-GET-`: `ITEMSTACK` (no components, standin-content §2), `TEXT` (text component as network NBT: plain string or `{"text":…}` / `{"translate":…,"with":[…]}`), `ENTITY-METADATA` entries used by `wire-profile.md`, `SLOT-DISPLAY` and `RECIPE-DISPLAY` (05b Recipe Book Add), `COMMAND-NODE` (05a Commands) |
| NBT (07 §1 to §3) | `NBT-WRITE-*` (compound begin/end, list begin/end, each tag type), `NBT-READ-*` (tree walk with path lookup), network root and file root framing |
| NBT files (07 §5.1) | `NBT-FILE-WRITE` / `NBT-FILE-READ`: a gzip-compressed NBT file with a named empty root, through GnuCOBOL `CBL_*` routines and `cc_deflate`/`cc_inflate` mode `CC_GZIP`; read outcome 0 ok, 1 unreadable or corrupt (the caller applies research R14). The one gzip NBT file path for `core` (world folder) and `client` (`servers.dat`, `options.dat`, reading `level.dat`) |
| Framing (01 §2, §3) | `PB-FRAME-ENCODE` (packet id + body → length-prefixed frame, compressed when threshold ≥ 0 and body ≥ threshold), `PB-FRAME-DECODE` (accumulating stream → next complete packet id + body, or "need more") |
| Chunk (06) | `CHUNK-SECTION-ENCODE` / `-DECODE` (paletted containers, single-value and linear palettes, biome container), `LIGHT-ENCODE` / `-DECODE` |

## 3. Wire fixtures (the client↔server contract artifact)

`contract/fixtures/wire/<phase>-<direction>-<hex id>-<name>[-<variant>].hex`: one packet body per file
(packet id first, then fields), whitespace-separated hex with `#` comments naming each field, written by hand
from `docs/protocol/` and `docs/protocol/09-cobolcraft-profile.md` (never generated by our own encoder).
There is one fixture per packet and variant that CobolCraft sends or accepts (the inventory is
`wire-profile.md` §3). Framing fixtures (`frame-*.hex`) cover uncompressed, compressed and below-threshold
frames.

## 4. Contract tests

- `proto/tests/contract_proto_primitives.cob`: every entry point against the 00/01/06/07 examples and the
  framing fixtures.
- `core/tests/contract_wire_server.cob`: every clientbound fixture equals what the core's packet builders
  produce for the fixture's stated inputs, and every serverbound fixture decodes to the stated values.
- `client/tests/contract_wire_client.cob`: the mirror image: every serverbound fixture equals what the
  client's builders produce, and every clientbound fixture decodes to the stated values.

## 5. Entry point parameters

Recorded with the US2, US3, US10 and US14 implementations of `proto` so that `core` and `client` call it the same way. It adds
no record shape: `PROTO.cpy` is unchanged. Every program is called `CALL "<name>" USING …` with every
argument by reference. Integers are `BINARY-LONG` unless stated. An *area* is any caller item at least as
long as the count passed with it; a *table* is a caller table of the stated item type (the callee addresses
both through a `BASED` view, so `-debug` checks the count, not a declared size).

**Errors.** A short or malformed read sets `PB-ERROR` = 1, leaves `PB-POS` where it was before the call and
yields 0 / empty. `PB-ERROR` stays set until `PB-RESET`: every later read yields zero bytes, so a caller can
decode a whole packet and test `PB-ERROR` once. A value a writer cannot encode (over-long string, invalid
identifier, bit outside a fixed set, unsendable frame) sets `PB-ERROR` and appends nothing.

| Program | Parameters |
|---|---|
| `PB-INIT` | `PB-BUFFER`, capacity (at least 16 bytes are allocated) |
| `PB-FREE`, `PB-RESET` | `PB-BUFFER` |
| `PB-APPEND-BYTES` / `PB-GET-BYTES` | `PB-BUFFER`, area (in / out), count |
| `PB-SKIP` | `PB-BUFFER`, count (advances `PB-POS`) |
| `PB-PUT-` / `PB-GET-` `BOOL`, `BYTE`, `UBYTE`, `SHORT`, `USHORT`, `INT`, `VARINT` | `PB-BUFFER`, value (`BINARY-LONG`; `BOOL` 0 or 1; writers keep the low bits of out-of-range values) |
| `PB-PUT-` / `PB-GET-` `LONG`, `VARLONG` | `PB-BUFFER`, value (`BINARY-DOUBLE`) |
| `PB-PUT-` / `PB-GET-` `FLOAT`, `DOUBLE` | `PB-BUFFER`, value (`FLOAT-SHORT`, `FLOAT-LONG`) |
| `PB-PUT-STRING` | `PB-BUFFER`, text area (UTF-8), byte length, maximum N in UTF-16 code units (00 §3.1) |
| `PB-GET-STRING` | `PB-BUFFER`, maximum N, text area out, capacity in bytes, byte length out |
| `PB-PUT-IDENTIFIER` | `PB-BUFFER`, text area, byte length |
| `PB-GET-IDENTIFIER` | `PB-BUFFER`, text area out, capacity, byte length out |
| `PB-PUT-` / `PB-GET-UUID` | `PB-BUFFER`, `PIC X(16)` (most significant byte first) |
| `PB-PUT-` / `PB-GET-POSITION` | `PB-BUFFER`, x, y, z |
| `PB-PUT-BITSET` | `PB-BUFFER`, Long count, table of `BINARY-DOUBLE` (00 §6.3 LongArray form) |
| `PB-GET-BITSET` | `PB-BUFFER`, capacity in Longs, Long count out, table out |
| `PB-PUT-` / `PB-GET-FIXED-BITSET` | `PB-BUFFER`, bit count n, area of ceil(n / 8) bytes (bit i = bit i mod 8 of byte i / 8) |
| `PB-PUT-` / `PB-GET-ANGLE` | `PB-BUFFER`, degrees (`FLOAT-SHORT`; written as floor(degrees × 256 / 360) in 8 bits, read as the signed byte × 360 / 256) |
| `PB-PUT-` / `PB-GET-LPVEC3` | `PB-BUFFER`, x, y, z (`FLOAT-LONG`; the writer sanitizes NaN to 0 and clamps to ±17179869183, 00 §4.6) |
| `PB-PUT-` / `PB-GET-TEXT` | `PB-BUFFER`, `PB-TEXT` (network NBT root, 09 §1 fixed form) |
| `PB-PUT-` / `PB-GET-ITEMSTACK` | `PB-BUFFER`, `PB-ITEMSTACK` |
| `PB-PUT-` / `PB-GET-ENTITY-METADATA` | `PB-BUFFER`, `PB-METADATA-ENTRY` (one entry, or the 0xFF terminator when `PB-MD-INDEX` = `PB-MD-END`; serializers other than those of `PROTO.cpy` set `PB-ERROR`; a read clears the value fields the serializer does not use) |
| `PB-PUT-` / `PB-GET-SLOT-DISPLAY` | `PB-BUFFER`, `PB-SLOT-DISPLAY` (types `empty`, `item`, `item_stack` with an empty DataComponentPatch; another type, or a read stack with components, sets `PB-ERROR`; a read clears the fields the type does not use) |
| `PB-PUT-` / `PB-GET-RECIPE-DISPLAY` | `PB-BUFFER`, `PB-RECIPE-DISPLAY` (one RecipeDisplayEntry: display id, RecipeDisplay `crafting_shapeless` or `crafting_shaped`, group, category, optional requirements each written and read as HolderSet selector 2 + one item id; the Recipe Book Add entry flags byte is the caller's; another type, a count above `PB-RECIPE-MAX-SLOTS` or another SlotDisplay type sets `PB-ERROR`) |
| `PB-PUT-` / `PB-GET-COMMAND-NODE` | `PB-BUFFER`, `PB-COMMAND-NODE` (one 05a CommandNode: flags byte, children, redirect when flag 0x08, name for types 1 and 2, parser and properties for type 2 (NumberRange for `brigadier:double` and `brigadier:integer`, kind for `brigadier:string`, none for `game_profile`), suggestions type when type 2 and flag 0x10; types 0 and 3 have no stub; the node count and root index of the packet are the caller's; flags outside 0 to 255, more than `PB-NODE-MAX-CHILDREN` children, a name longer than `PB-CN-NAME`, another parser, a string kind outside 0 to 2, range flags outside 0 to 3 or an invalid or over-long suggestions type sets `PB-ERROR`; a read clears the fields the node does not use) |
| `NBT-WRITE-BYTE`, `-SHORT`, `-INT` | `PB-BUFFER`, name area, name length, value (`BINARY-LONG`) |
| `NBT-WRITE-LONG`, `-FLOAT`, `-DOUBLE` | `PB-BUFFER`, name area, name length, value (`BINARY-DOUBLE`, `FLOAT-SHORT`, `FLOAT-LONG`) |
| `NBT-WRITE-STRING` | `PB-BUFFER`, name area, name length, text area (UTF-8), byte length |
| `NBT-WRITE-BYTE-ARRAY` / `-INT-ARRAY` / `-LONG-ARRAY` | `PB-BUFFER`, name area, name length, count, area / table of `BINARY-LONG` / table of `BINARY-DOUBLE` |
| `NBT-WRITE-LIST-BEGIN` | `PB-BUFFER`, name area, name length, element type, count; then the elements (name length -1) |
| `NBT-WRITE-COMPOUND-BEGIN` | `PB-BUFFER`, name area, name length; then the entries |
| `NBT-WRITE-COMPOUND-END`, `NBT-WRITE-LIST-END`, `NBT-WRITE-END` | `PB-BUFFER` (End tag; nothing; a network End root = absent) |
| `NBT-READ-ROOT` | `PB-BUFFER`, framing (0 network, 1 file: named compound root), type out; `PB-POS` left at the payload |
| `NBT-READ-COMPOUND-NEXT` | `PB-BUFFER`, type out (0 = End), name area out, capacity, name length out |
| `NBT-READ-LIST-BEGIN` | `PB-BUFFER`, element type out, count out |
| `NBT-READ-STRING` | `PB-BUFFER`, text area out (UTF-8), capacity, byte length out |
| `NBT-READ-BYTE-ARRAY` / `-INT-ARRAY` / `-LONG-ARRAY` | `PB-BUFFER`, capacity, count out, area / table out |
| `NBT-READ-SKIP` | `PB-BUFFER`, type (skips one payload, any nesting up to 512) |
| `NBT-READ-FIND` | `PB-BUFFER`, container type (9 or 10, payload at `PB-POS`), path area (`a.b[2].c`), path length, found type out (0 = not found, `PB-POS` unchanged) |
| `NBT-FILE-WRITE` / `NBT-FILE-READ` | path area, path length, `PB-BUFFER` (named-root NBT stream), outcome out (0 ok, 1 cannot write / unreadable or corrupt) |
| `PB-FRAME-ENCODE` | frame `PB-BUFFER` (appended to), packet `PB-BUFFER` (id + body), threshold (< 0 = compression off) |
| `PB-FRAME-DECODE` | stream `PB-BUFFER` (from `PB-POS`), packet `PB-BUFFER` (caller-initialised; id + body, `PB-POS` after the id), threshold, validate (1 = reject compressed packets below the threshold, server side), packet id out, outcome out (0 packet, 1 need more, 2 malformed) |
| `CHUNK-SECTION-ENCODE` | `PB-BUFFER`, non-empty count, fluid count, block states (table of 4096 `BINARY-LONG`, index y·256 + z·16 + x), biomes (table of 64, index y·16 + z·4 + x), block global palette bits, biome global palette bits |
| `CHUNK-SECTION-DECODE` | `PB-BUFFER`, block global palette bits, biome global palette bits, non-empty count out, fluid count out, block states out, biomes out |
| `LIGHT-ENCODE` / `LIGHT-DECODE` | `PB-BUFFER`, light section count (at most 256), sky states (table of `BINARY-LONG`: 0 no information, 1 empty, 2 array), sky arrays (table of `PIC X(2048)`), block states, block arrays |

NBT writer name length: ≥ 0 a named tag (a file root is a compound with name length 0); -1 payload only
(list elements); -2 a network root (type byte, no name). Scalar NBT payloads are read with
`PB-GET-BYTE`/`-SHORT`/`-INT`/`-LONG`/`-FLOAT`/`-DOUBLE` (same encodings, 07 §1). Programs not in this
table (`PB-PUT-BE-INTEGER`, `PB-GET-VARNUM`, `NBT-PUT-MUTF8`, `CHUNK-CONTAINER-ENCODE`, `LIGHT-PUT-MASK`, …)
are internal to `proto`.
