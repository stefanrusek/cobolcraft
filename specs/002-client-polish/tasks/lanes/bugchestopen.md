## Phase bugchestopen (lane bugchestopen, operator report of try19 in a skyblock world: "chests can only be opened if there is no solid block above them, but we are not allowing them to be opened with ANY block above them: a chest on top of a chest makes the bottom chest unusable. Also copper chests don't open"; T63100-T63199)

Root cause (core, two separate causes). (1) `MENU-CONT-OPEN` (core/src/menu-container.cob) took "a conductor above" to mean `CB-SOLID = 1 AND CB-OPAQUE = 1` of the block above, which is true of a chest, slab, stairs and every other block whose flags do not say noOcclusion, so a chest, slab or stairs above a chest kept it shut. Vanilla `ChestBlock.isChestBlockedAt` (31-1 section 10.2) refuses only for a redstone conductor above (30-1 section 2.4: the collision shape is a full cube, less the never list, plus the always list) or a cat in the sitting pose in the box above; the sitting cat was not checked at all. (2) `BE-BLOCK-FAMILY` (core/src/be-world.cob) knew only `chest` and `trapped_chest` as the chest family, so the eight copper chest blocks (31-1 section 3.1: the chest block entity type covers them) were not containers for the open path (no block entity wiring of the menu, family 0).
