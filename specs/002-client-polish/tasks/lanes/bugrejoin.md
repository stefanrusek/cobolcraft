## Phase bugrejoin (lane bugrejoin, finding of lane bugchat: quitting a single-player world through the pause menu and opening a world again ended in "No reply arrived in time"; T30900-T30999)

- [x] T30900 [bugrejoin] Test first `client/tests/test_rejoin.cob` (red before the fix, output scratchpad/red-rejoin.txt): join world A, quit through the pause menu (Escape, Save and Leave the World) with nothing owed (control, passes), then with a block break in progress when Escape is pressed, open the same folder (and another folder) again: joined, in play, no message, still in play after 700 frames. Before the fix the same-folder rejoin ended on the server list with "No reply arrived in time". Not reproducible with the quit alone: the break in progress makes the client's Escape frame send a Player Action (abort) the core acknowledges at its next tick, which the paused host never runs
- [x] T30901 [bugrejoin] Test first `core/tests/test_ack_leave.cob` (red before the fix: `owed 8`, expected `owed 0`): a connection that ends with a Block Changed Ack still owed leaves nothing in `BC-ACK` for its id
- [x] T30902 [bugrejoin] Root cause (core, not client or shim): `BC-ACK` (`core/copy/BCHANGE.cpy`, the highest block-change sequence a connection owes as Block Changed Ack, indexed by connection id) was never cleared when a connection ended. The pause menu holds the core ticks, so the ack of the last Player Action was still owed when Save and Leave ended the connection. The next world's connection took the same id (lowest free), `WORLDSIM-ACKS` sent it that ack at its first tick (the id has a player row from the login), the client was in its configuration phase where clientbound id 4 is Keep Alive and answered it with a Keep Alive of value 0, the core had no keep-alive pending (`CORE-KEEPALIVE-ANSWER`) and disconnected it with `disconnect.timeout`. Any host is affected (the dedicated server too: a connection that ends within a tick of a block action, then a new connection with that id). The direct `SP-QUIT` path never showed it because no frame (and no packet) came between the last tick and the quit
- [x] T30903 [bugrejoin] `core/src/blockupd-29.cob` `BC-ACK-CLEAR` (id): drops the ack a connection owes; `core/src/session.cob` calls it from `SESSION-RELEASE` (the connection ends) and `SESSION-OPEN` (a new connection owes nothing, whatever a world reset left)
