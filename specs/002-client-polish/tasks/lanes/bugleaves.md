## Lane 002-lane-bugleaves (T62100+)

Operator report from the try19 play (screenshots against regular Minecraft): "when leaves are fancy they have transparent spots, and so all the leaves are rendered, but we only render the outermost leaves which makes trees look less full"; and a large dark patch on the ground under the tree that vanilla does not show. No existing open task covers either. Docs: 24 part 1 section 9.1 (`LeavesBlock.skipRendering`: true only when the static `cutoutLeaves` option is off and the neighbour is a leaves block; leaves have `noOcclusion`, an empty occlusion shape, and light dampening 1), 29b-3 section 5 (client face culling: with cutout leaves on, which is the default, leaves cull like any other block, and an empty occlusion shape hides nothing), 13 section 7.5 (option `cutoutLeaves`, default true; the Fast preset sets it false), 12 section 2.4 (alpha cutoff of the terrain cutout pipelines).

- [x] T62100 [US3-client] (lane bugleaves) Root cause found (client, state tables and mesher; not core, not shim): `STATE-TABLES-BUILD` gave every non-occluding block that fills the cube (`BSH-OUT` = 1, so leaves too) `ST-LIKE` 1, and the mesher hid a face against a neighbour of the same block with it, so a leaf block drew only the faces towards air or other blocks (Fast behaviour, and only between two leaves of one kind). Red first: `client/tests/test_mesher_leaves.cob` (the generated vanilla pack of CC_GENERATED_DIR, the standard content set): a 3 x 3 x 3 block of oak leaves across a chunk and a section border drew 54 quads (expected 162), oak beside birch leaves 12 with the option off (expected 10).
- [x] T62101 [US3-client] (lane bugleaves) `client/src/state-tables.cob`: a leaves block (class holds `Leaves`) is flagged `ST-LEAF` (new table in `client/copy/CLSTATE.cpy`) and is no `ST-LIKE` block; `client/src/mesher.cob` MESH-SECTION: one flag test, `CL-LEAVES-CULL = 1 AND ST-LEAF(own) AND ST-LEAF(neighbour)`, hides the face (any two leaves blocks, as `LeavesBlock.skipRendering`); with the flag at 0, the default (Fancy: `cutoutLeaves` true), every leaf block draws all six faces and the face towards a stone is still hidden by the stone's own covering face while the stone's face towards the leaves is drawn (leaves occlude nothing). No per-cell table scan is added: the new test sits behind the one flag.
- [x] T62102 [US3-client] (lane bugleaves) `client/src/options.cob` OPTIONS-APPLY reads the option `cutoutLeaves` into `CL-LEAVES-CULL` (false = 1); a change meshes every loaded section again (`WORLD-DIRTY-ALL`, `client/src/world-replica.cob`), applying the same value again marks nothing. `client/tests/test_state_like.cob` now expects leaves as `like 0 leaf 1`. Cases of `test_mesher_leaves`: default flag 0, 3 x 3 x 3 fancy 162 / fast 54, oak beside birch 12 / 10, leaf beside stone 11 in both modes (stone 6), leaf quads in the opaque list (none translucent), the option false / true / unchanged and the 48 sections marked.
- [x] T62103 [US3-client] (lane bugleaves) Transparent texel handling checked, no change needed: leaf sprites have only alpha 0 or 255 texels, so `ATLAS-TRANSLUCENT` is 0 and their quads go to the opaque list (asserted in `test_mesher_leaves`); `shim/shaders/world.frag` discards a texel with alpha under 0.1 (12 section 2.4 gives 0.5 for the terrain cutout pipelines; the two differ only for partial alpha texels, which a binary-alpha leaf sprite does not have) and the world atlas has no mip levels (nearest sampler), so no alpha-coverage loss happens on distant leaves and the holes are drawn as in the reference.
- [x] T62104 [US3-client] (lane bugleaves) Dark patch under the canopy, audited: leaves are NOT opaque to sky light. Core: `LIGHT-SKY` (`core/src/light.cob`) takes `CB-S-DAMP` 1 for leaves (`test_light_plants.cob` reads leaves 14, the air under it 13), and `CB-OPAQUE` is 0 for them; client: `ST-OPAQUE` 0 for leaves, so `SKY-STOPGAP` does not treat a canopy as a surface either. The patch is the column-only sky light of the stored chunk light ("no sideways spreading", `core/src/light.cob` header; the 32 section 5.2 engine spreads light sideways into the dark cells under a canopy, so the cells under the canopy centre read about 15 minus the horizontal distance to the open sky, where the stand-in reads 15 minus the leaves above minus one per air cell under them). Nothing to fix on the leaves; the real cure is the engine switch (T0697 / L32), out of scope for this run by the operator's standing rule.
