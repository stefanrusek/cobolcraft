## Lane 002-lane-perfsteady (T59000-T59299)

Operator report on try16 (db901a9a, release build): "really bad" performance, the operator gave up testing (earlier: village very laggy, 44 fps in a stronghold, 0 fps for the first minute after a load or a respawn (lane bugstall), shaking over height differences (lane bugstep)). Base: origin/002-client-polish db901a9a, plus bugstall's fix dba39f8c (a fluid tick at a chunk edge, cherry-picked for the measurement: without it a standard world does not finish loading in the bench; the same patch, so the merge is clean). Measured, not guessed: user CPU (C clock()), release build (-O2, FPFAST=1), the load average is printed with every result.

- [x] T59000 [US3-client] (lane perfsteady) Measurement program `tests/convergence/bench_steady_client.cob` (not an acc test, built by hand: scratchpad/perfsteady/mkbench.sh against the static libraries, mkbench2.sh against the dylibs so that `sample` names the programs; prints `BS ...` lines).
