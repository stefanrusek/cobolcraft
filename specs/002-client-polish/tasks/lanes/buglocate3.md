## Lane 002-lane-buglocate3 (T43400-T43499; operator try15: `/locate structure #minecraft:village` works but `/locate structure village` does not; an ender eye "doesn't throw into the air")

What vanilla does (docs only, 16 section 7.7 and 15 sections 6.7 and 14): the structure argument is a `resource_or_tag_key`; a plain identifier is a registry KEY that the parser does not look up, and the command resolves it: an identifier that names no structure of the registry is `commands.locate.structure.invalid` ("There is no structure with type "%s""). `village` and `minecraft:village` name no structure (the villages are village_plains, village_desert, village_savanna, village_snowy, village_taiga and the tag #minecraft:village; no alias is in the docs), so vanilla refuses them too. CobolCraft refused them with the parser's `argument.resource.not_found` (wrong message), gave no tab completion for the structure argument, and the singleplayer client of the report showed the message untranslated only where the generated vanilla language was not in the pack stack (a test setup effect, see T43403).
