The PROBE numbers of test_struct_gate4_real (4820/5490/5310 ms) were cold every time because that probe calls STRUCT-GATE-RESET and STRUCT-GATE-ON before each run (a new SD-EPOCH empties the start list cache and the store; the 'with it' run is therefore a cold start), not a repeated assembly. Measured in one process (start chunk (-135,-60), 272 pieces, 542 junctions): first STRUCT-FIND-POINT 3490 to 3870 ms, second 0 ms (memo); start chunk with every cache empty 6320 to 6810 ms, warm 1630 to 1870 ms; east neighbour cold 4390 to 4710 ms, warm 1080 to 1140 ms; chunks without the start 810 to 860 ms. A worker forked with empty caches makes the start chunk and then the neighbour byte equal to the atomic chunks (the cost is once per worker process, up to GW-MAX 8 workers each paying about 4 s the first time a start enters their windows). Cold profile (sample, 10 ms): JIG-ASSEMBLE 331 of which template loading 217 (STRUCT-TPL-BLOCKS 115, NBT-FILE-READ 63, STRUCT-TPL-ORDER 18, palette states 16: the state lookup is 4 percent, so a state memo is not the lever). Warm, the start chunk costs 0.8 to 1.0 s more than a chunk without the start and 44 percent of its samples are STRUCT-BEARD-SAMPLE (RIGID 205, JUNCTION 126 of 559); replacing the arithmetic of its record prefilter by comparisons of pre-offset coordinates (tried, exact, 154 cases of the five beardifier programs green) changed the warm start chunk from 1700/1870 ms to 1630 ms: within noise, not kept. What would cut the cold cost is loading a template lazily (the assembly needs the size and the jigsaw blocks, placement needs the block list), or sharing an assembled start between workers; both are larger designs, not built.
