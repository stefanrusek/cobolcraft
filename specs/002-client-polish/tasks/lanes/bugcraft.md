## Lane 002-lane-bugcraft (T49000+)

Operator report from the try15 play: "I couldn't craft anything in the crafting bench" in a NEW superflat world created on relaunch (earlier in the same session, in a standard world, planks and sticks crafted through the bench). Base of the lane: 002-lane-bughang 2fe11c3b (try15 plus the reopened superflat world type fix). Lane bughang had ruled out a partial `generated/` (T46208).

- [x] T49000 [US10] (lane bugcraft) Root cause found, in the core (not the client, not the shim, not the data): `WORLD-RECIPES-OPEN` (core/src/world-recipes.cob), called by `WORLD-CONTENT-OPEN` with the decided world type, loaded the data pack recipes (`RECIPES-LOAD`) for the types `standard` and `debug` only. The type `superflat` (the standard content set with the flat generator: `WORLD-CONTENT-OPEN` already opens the standard registries for it) fell into the ELSE branch and got `BUILTIN-RECIPES-LOAD`, the ten cobolcraft stand-in recipes, so in a superflat world no vanilla grid matched (log, planks, sticks, crafting table, everything) while the item and block tables were the vanilla ones; the recipe book (recipe store) was equally wrong. A reopened superflat world is affected the same way (the client asks for cobolcraft, `WORLD-TYPE-DECIDE` takes superflat from the level.dat, and that decided type reaches `WORLD-RECIPES-OPEN`). Affected: superflat (new and reopened). Not affected: standard, debug, cobolcraft (compared in the same test).
- [x] T49001 [US10] (lane bugcraft) Red first: `core/tests/acc_bugcraft_flat_craft.cob` (real data, CC_GENERATED_DIR; skipped as a pass without it) drives the real packet path (Use Item On a crafting table, Container Click pick up / place / take with the bench's container id) for a log (planks x4), four planks (crafting table) and two planks (sticks x4) in a new superflat world, a saved and reopened superflat world (request cobolcraft), a standard world and a debug world. Before the fix the superflat case observed `nothing, nothing, nothing` (the standard and debug cases passed).
- [x] T49002 [US10] (lane bugcraft) Fix: `core/src/world-recipes.cob` loads `<generated>/vanilla-data` recipes for `superflat` too. The loot half of the same content set was checked: `core/tests/acc_bugcraft_flat_loot.cob` (guard: stone with a wooden pickaxe drops cobblestone, the hand nothing, diamond ore with an iron pickaxe a diamond, in a new superflat world) passes without a change, because the block loot tables come through the content registries; `WORLD-LOOT-OPEN` is left as it is.
