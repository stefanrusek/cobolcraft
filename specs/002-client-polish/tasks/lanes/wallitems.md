## Phase wallitems (lane wallitems, rest of CC-0009 and T30040; T33000-T33299)

Open ticket CC-0009 (block placement honours orientation and attachment) and the open task T30040 of lane bugtorch (standing signs, ladders, levers, buttons, banners and tripwire hooks placed with the default state of the item). The operator's old report "I couldn't break torches" (CC-0009 FR-005) is investigated here too.

- [x] T33000 [wallitems] FR-005 "I couldn't break torches": reproduced through the real Player Action path on the current build, and it does not reproduce. Test `core/tests/acc_break_soft_standard.cob` (superflat standard world, real data): in survival and in creative with an empty hand Start Destroy Block removes torch, soul torch, redstone torch, copper torch, the four wall torches, dandelion, poppy, short grass, fern, dead bush, sapling, red mushroom, sugar cane, wheat, tall grass, tripwire and redstone wire, the Stop Destroy Block that follows changes nothing, the player is left with no break state. Test `tests/convergence/acc_wallitems_break.cob` (client, memory connection and core in one process): aiming the look ray at a torch, a redstone torch, a wall torch, a redstone wall torch, a poppy and short grass and holding the left button removes it from the core and from the client's replica in both modes (the case also asserts the block was there before). The cause of the old symptom was the Start Destroy Block refusal of blocks with a zero break time that `test_break_instant` already covers (operator report of try6); nothing in targeting (`RAYCAST` hits the outline shape of a torch where it is, `test_physics_shapes`), the client's zero break time (`CONTROLS-BREAK-TIME`) or the core is left that stops a torch from being broken. Neither the core nor the client changed for this task.
