## Lane 002-lane-bugtrade (T42700+)

Operator report (try15): "can't interact with villagers (farmer)": right click on a villager did nothing. Two independent causes, each hiding the other.

Trading flow before the lane: villager takes a profession (workstation, CORE-TICK) works; core Interact -> Open Screen + Container Content + Merchant Offers works when the packet is fed (acc_us15_merchant_interact, and now on a village villager in a generated world); Select Trade, result slot, taking, xp orb, uses, out of stock work in core tests; client merchant screen reads offers and renders (test_screen_40_5). Broken: (1) the client's look ray never met a villager; (2) once the core did open the window, the next tick closed it.

- [x] T42700 [US15-client] Root cause 1 (client): `ENTITY-ATTACK-BOX` (client/src/entities-replica.cob) gave a hit box only to entities whose registry category is not MISC (plus boats, minecarts, armor stands, end crystals). 21 section 3 lists the villager, iron golem, snow golem, copper golem and mannequin as MISC, so a standard-set villager had no target box: no Interact was ever sent (and the golems could not be hit). The MISC living mobs now get the box. Red first: `acc_bugtrade_villager_target` (client; real registry rows through `CONTENT-ENTITY-BY-KEY`: villager, iron_golem, snow_golem, copper_golem, mannequin aimed at 2.5 blocks ahead were not the ray target: 5 of 9 cases failed; wandering_trader (CREATURE) was already hit, arrow, item and area_effect_cloud stay not hit). The older `acc_us15_villager_interact` used a stand-in entity (EN-VANILLA 0), which has its own table, so it never saw the registry path.
- [x] T42701 [US15-core] Root cause 2 (core): `MENU-STILL-VALID` (core/src/menu-lifecycle.cob) treated MN-BENCH-X/Y/Z of every menu with own slots as a block position and applied the block reach (eye to unit box under 8.5 blocks) after `MENU-CONT-VALID`. For the merchant window (family 29) MN-BENCH-X is the entity id (MN-BENCH-Y/Z 0), so the check measured the distance to the cell (entity id, 0, 0) and `MENU-TICK` closed the window (Container Close) on the first tick after it opened. Every earlier test drained right after the click. A merchant window is now valid exactly when `MERCHANT-VALID` says so (alive, same dimension, within 4 blocks, 40-5 section 2.9). Red first: `acc_bugtrade_village` "three ticks later the trading window is still open" (observed closed), and convergence `acc_bugtrade_trade` (the client screen opened and closed again inside one frame).
- [x] T42702 [US15-core] `MERCHANT-INTERACT`: a sleeping villager ignores the click, a baby villager is refused with no window (19 section 22.4 mobInteract; the head shake and its sound are not modelled, see T42704). Red first: `acc_bugtrade_village` "a baby villager with a profession opens no window", "a sleeping villager opens no window".
- [x] T42703 [US15-core] Acceptance `acc_bugtrade_village` (core): a superflat world (seed 12345) from the generated packs, its first village generated round the player, 600 ticks (villagers take professions as in the game); every villager of the village is right clicked through the real Interact packet: Open Screen + Merchant Offers for a grown villager with a profession (farmer, weaponsmith), nothing for none/nitwit/baby; the window stays open while the villager is within 4 blocks and closes beyond. Convergence acceptance `acc_bugtrade_trade`: client + core through the single-player host, a villager with a composter beside it becomes a farmer, the Player is taken next to it, looks at it and presses the right button: the client opens the trading screen with the offers.
