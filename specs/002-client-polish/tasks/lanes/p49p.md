## Lane p49p (T35000-T35499)

Scope: continuation of lane p49h (doc 44 part 3): a memory model so that the villager brain units of lane p49h run in the game (memory store, sensors on their intervals, the activity schedule, a walk target consumed by the standard mob step's path walk), replacing the simplified VL-BRAIN step by step. Performance is measured with `core/tests/test_p49p_bench.cob` (CPU microseconds per villager tick, 40 villagers: work / meet / rest).

- [x] T35000 [US15-core] (lane p49p) 44-3 sections 2 and 18 section 4.5 memory store: `core/copy/VLMEM.cpy` (EXTERNAL, one entry per VL slot: memory type id, global position, two numbers, expiry tick; the activity; the behaviour timers), `core/src/mob-vil-mem.cob` (VM-GET, VM-PUT, VM-ERASE, VM-HAS, VM-CLEAR; the claimed points home, job_site, potential_job_site and meeting_point read and write through the claim table of VILPOI.cpy), VL-FIND and VL-REMOVE clear the slot; test `core/tests/test_p49p_mem.cob`.
- [x] T35001 [US15-core] (lane p49p) 44-3 sections 2.12, 2.14, 3.1 activities: `core/src/mob-vil-act.cob` (VM-ACT-TICK, VM-ACT-SET, VM-ACT-RESET: the schedule's activity until a special one, panic, pre_raid, raid or hide, is entered and until updateActivityFromSchedule); VL-BRAIN uses it; test `test_p49p_mem`.
- [x] T35002 [US15-core] (lane p49p) 44-3 sections 2.5 and 2.17 walking: `core/src/mob-vil-walk.cob` (VL-WALK-SET, VL-WALK-TICK, VL-WALK-GY, VL-WALK-STOP: the walk_target memory drives the path walk of STDMOB-HEAD, ends on arrival, and a walk that ran out of time leaves cant_reach_walk_target_since); VL-BRAIN is split into VL-BRAIN (per tick), VL-BRAIN-BEAT, VL-BRAIN-WALK (GoToPotentialJobSite and SetWalkTargetFromBlockMemory through Q3-BLOCKMEM) and VL-BRAIN-SLEEP; test `test_p49p_mem` and the existing villager tests.
- [x] T35003 [US15-core] (lane p49p) performance baseline: `core/tests/test_p49p_bench.cob`, `core/tests/VILLTEST.cpy` (village scene helpers).
- [x] T35004 [US15-core] (lane p49p) 44-3 sections 2.10 to 2.12, 2.14, 2.17 core behaviours and activities: `core/src/mob-vil-core.cob` (VL-CORE-TICK, run every tick by VL-BRAIN: VillagerPanicTrigger and VillagerCalmDown from hurt_by and nearest_hostile, ReactToBell, SetRaidStatus and ResetRaidStatus, SetHiddenState, LocateHidingPlace in HIDE and RAID, RingBell in PRE_RAID; PRE_RAID walks to the meeting point), `core/src/mob-vil-bell.cob` (VL-BELL-RING: the villagers within 32 blocks hear the bell), VL-FEAR-STEP writes the nearest_hostile memory, VL-HURT-BY writes hurt_by and hurt_by_entity (40 ticks); test `core/tests/acc_us15_villager_activity.cob` (red: link failure before VL-BELL-RING).
