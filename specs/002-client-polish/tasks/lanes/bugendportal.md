## Lane 002-lane-bugendportal (T46000+)

Operator report from the try15 play: "placing eyes of ender uses the eye and you can't use one more than once on an empty end portal block, but the block doesn't update and the portal doesn't open". Base of the lane: 002-try15 6789c8b5. Docs: 39-portals section 7.2 (EnderEyeItem.useOn), 25 section 6.3, 29 section 7 (change set and broadcast), 24-4 section 6.20 (end_portal_frame states).

- [x] T46000 [US12-core] (lane bugendportal) Root cause (core, not client, not shim): `PORTAL-EYE-PLACE` (core/src/portal-39b.cob) wrote the frame's new state and the nine `end_portal` cells with the raw chunk write `WORLD-SET-BLOCK`, which does not join the tick's change set, so no Block Update or Section Blocks Update ever reached a viewer. The core state was right (the eye was consumed, a second eye on that frame was refused, Level Events 1503 and 1038 were sent, the ring pattern matched with the right `eye` and `facing` names and registry state ids), but every client kept the empty frame and no portal blocks. Not a `has_eye` name mismatch: the registry and the core use `eye` (30-2 section 5.3 says `has_eye`; that is a doc naming slip, the comparator output is not wired in this world).
- [x] T46001 [US12-core] (lane bugendportal) `core/tests/acc_f2us12_end_portal_open.cob` (red first): a standard world with real data, a ring of 12 frames at y 150 (stronghold facings: north row at the maximum z, south row at the minimum z, west at the maximum x, east at the minimum x), Alice (operator, survival) and Bob watching the ring chunks (teleport tail `CHUNKS-FOLLOW`, ticks until the far chunk is loaded, keep-alives answered). Through the real Use Item On packet: an eye on an empty frame sets `eye` true (world state = registry state of eye=true plus the facing), Alice and Bob both get the Block Update with that state id and Level Event 1503, the survival stack loses one, the ring is incomplete so no 1038 and no portal; a second eye on the same frame keeps the item and sends no Level Event; the eye in the last frame sends the frame's update and the nine interior cells as `end_portal` in one Section Blocks Update to both viewers, replaces the stone put in the interior, sends the global Level Event 1038 at (202, 150, 202); a second ring built with `/setblock` (eye=true frames, the last one eye=false) opens the same way. Failed before the fix on exactly the six Block Update / Section Blocks Update cases (13 passed, 6 failed), passes after (19 of 19).
- [x] T46002 [US12-core] (lane bugendportal) Fix: `PORTAL-EYE-PLACE` writes the eye state and the nine `end_portal` cells with `LEVEL-SET-BLOCK` flags 2 (39 section 7.2: set `eye` true with flags 2, set `end_portal` with flags 2) after `WORLDSIM-ENSURE`, as portal-39.cob does for nether portals, so the changes are broadcast by `BC-BROADCAST` at the end of the tick.
