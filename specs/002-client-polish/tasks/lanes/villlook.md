## Lane 002-lane-villlook (T11200+)

Operator report on the release build: villagers render naked (no biome clothing, profession outfit or level badge). The client layers (34-3 section 1.5) were already implemented and the textures are extracted; two causes were found.

- [x] T11200 Server sends the villager's look (34-3 1.5, 46 section 6, 19 section 22): the core never sent VILLAGER_DATA (entry 19, serializer 18). `core/src/mob-villook.cob` VILLOOK-CODE (type id, profession id of 46 section 6.2, level from the VL- side table), VILLOOK-DATA (the entry), VILLOOK-CHANGED and VILLOOK-SYNC (a look not seen before is sent to the viewers; called after VL-STEP in `core/src/stdmobs.cob`); `core/src/mob-18-8.cob` MOB-DATA-VALUES marks a non-default villager as needing data and MOB-DATA-BUILD appends the entry. Test `core/tests/test_villager_look.cob` (red: link failure on VILLOOK-CHANGED/VILLOOK-SYNC).
- [x] T11201 Client default villager data (34-3 1.5: no `villagerData` means no layers, but a villager always has it, default plains/none/level 1, and a server sends only non-default values): `client/src/entities-replica.cob` gives a new villager or zombie villager row the default data, so the plains type layer is drawn; `client/tests/test_entity_overlays.cob` cases "spawned without data" (red before: layer 1 gave 0).
- [x] T11202 Regression and coverage: `make cover-changed SINCE=origin/002-client-polish ONLY="test_villager_look test_entity_overlays"` 0 uncovered changed lines; `make lint` clean; core `*vil*`, `test_mob_19_*`, `test_mob_18*`, `acc_us15_*`, `test_entity*` and client `test_entit*`, `test_entmodel_34_3*` pass.
- Gap: the zombie villager's own villager data (20 conversion, 45-6 NBT) is not kept by the core, so a zombie villager is drawn with the default (plains) look; the wandering trader needs no data (34-3 1.6 plain texture).
