## 1. Shared Brain behaviours

### 1.1 Long jump family

Three behaviours share the memories `LONG_JUMP_COOLDOWN_TICKS`, `LONG_JUMP_MID_JUMP` and `LOOK_TARGET`.

**`LongJumpToRandomPos(cooldownRange, height, width, velocityFactor, jumpSoundOf, landingTest)`** (time-out 200 ticks; start needs the memories `LONG_JUMP_COOLDOWN_TICKS` and `LONG_JUMP_MID_JUMP` absent). Constants: 20 tries (`FIND_JUMP_TRIES`), preparation 40 ticks, walking-path distance 8, allowed launch angles 65, 70, 75, 80 degrees. The argument order is read from the field assignments: second integer is the height (vertical half-extent), third the width (horizontal half-extent). The doc 19 frog row's "height 2 to 4" therefore means height 2, width 4.

1. Start condition (`checkExtraStartConditions`): the mob is on the ground, not in water or lava and not standing in a honey block. When this fails, the cooldown memory is set to `sample(cooldownRange) / 2` (integer division) and the behaviour does not start.
2. `start`: no chosen jump, tries = 20, remember the start position, and list every block position in the box (x +/- width, y +/- height, z +/- width) except the mob's own block, each with weight `ceil(distanceSqr to the mob's block)`.
3. Each tick while no jump is chosen: tries -= 1 and `pickCandidate`: while candidates remain, draw one by weight (farther is likelier) and remove it from the list; reject it if its horizontal position equals the mob's or if the landing test fails (default landing test: the block below the candidate is a full-render solid, and the mob's path malus for the path type of the candidate position itself, taken from `WalkNodeEvaluator.getPathTypeStatic(mob, candidate)`, is 0); compute the jump vector (step 5); if none exists, reject; set `LOOK_TARGET` to the block; reject the candidate when a walking path to it exists and can reach it (navigation `createPath(pos, 0, 8)`); otherwise choose this jump and store the current game time as the preparation start.
4. Once a jump is chosen and 40 ticks have passed: set the yaw to the body yaw, set discard-friction, set the motion to the chosen vector scaled by `(|v| + jump boost power) / |v|`, set `LONG_JUMP_MID_JUMP` true and play the jump sound (source neutral, volume 1, pitch 1).
5. The behaviour continues while the start position is unchanged, tries > 0, the mob is not in water and (a jump is chosen or candidates remain). When it ends and `LONG_JUMP_MID_JUMP` is still absent, the cooldown is set to `sample(cooldownRange) / 2` and `LOOK_TARGET` erased.

**Jump vector** (`LongJumpUtil.calculateJumpVectorForAngle(mob, target, maxSpeed, angleDeg, checkCollision)`), called for each of the four angles in random order (a shuffle) with `maxSpeed = jump_strength attribute x velocityFactor` and `checkCollision = true`; the first angle that yields a vector wins.

1. P = mob position, T = centre of the target block. `d = normalize(T.x - P.x, 0, T.z - P.z) x 0.5`. `T' = T - d` (aim half a block short). `r = T' - P`.
2. `theta = angleDeg x pi / 180` (as float). `phi = atan2(r.z, r.x)`. `A = r.x^2 + r.z^2`, `H = sqrt(A)`, `dy = r.y`, `g` = the mob's gravity (`Mob.getGravity`).
3. `v^2 = A x g / (H x sin(2 theta) - 2 x dy x cos^2(theta))`. If `v^2 < 0` there is no vector. `v = sqrt(v^2)`; if `v > maxSpeed` there is none.
4. `vh = v cos(theta)`, `vy = v sin(theta)`.
5. If collisions are checked: `n = 2 x ceil(H / vh)`; step `i` from 0 to `n - 2`: `t += H / n` (t is the horizontal distance so far), `y = tan(theta) x t - (t^2 x g) / (2 x v^2 x cos^2(theta))`, point = `P + (t cos phi, y, t sin phi)`; every consecutive pair of points must pass `isClearTransition` (below) in the LONG_JUMPING pose dimensions, otherwise there is no vector.
6. The result is `0.95 x (vh cos phi, vy, vh sin phi)`.

`isClearTransition(from, to)`: `w = min(width, height)` of the dimensions; `steps = ceil(|to - from| / w)`; walk from `from`, each step moving `0.9 x w` along the direction (the last step lands on `to`); every position must have no collision for the dimensions' box.

**`LongJumpMidJump(cooldownRange, landingSound)`** (time-out 100; needs `LONG_JUMP_MID_JUMP` present): `start` sets discard-friction and the pose LONG_JUMPING; it continues while the mob is off the ground; on `stop`, if on the ground: horizontal motion multiplied by (0.1, 1, 0.1), landing sound (neutral, volume 2, pitch 1); then discard-friction off, pose STANDING, `LONG_JUMP_MID_JUMP` erased, `LONG_JUMP_COOLDOWN_TICKS` set to `sample(cooldownRange)` (the full value; the prepare path used half).

**`LongJumpToPreferredBlock(cooldownRange, height, width, velocityFactor, soundOf, tag, chance, landingTest)`**: as the random-position behaviour, with a different candidate draw. At `start` it rolls once: "wanting preferred" if `nextFloat < chance` (frog 0.5). If not wanting preferred it behaves exactly as `LongJumpToRandomPos`. If wanting preferred it repeatedly draws a candidate by weight; a candidate whose block directly below is in the tag is returned at once, others are appended to a "not preferred" list; when the candidates are exhausted it returns the first of the not-preferred list (removing it), so a jump is still found when no preferred block is in range.

### 1.2 Land and liquid finders (frog)

All three are one-shot behaviours that need `ATTACK_TARGET` and `WALK_TARGET` absent and `LOOK_TARGET` registered. Each keeps a private "next allowed time" counter initially 0 and works only when the mob's block fluid state matches (stated per behaviour). On success they set `LOOK_TARGET` to a block tracker and `WALK_TARGET` to that block with the given speed and completion range.

| Behaviour | Parameters | Runs when | Cooldown handling | Search |
|---|---|---|---|---|
| `TryFindLand(radius, speed)` | idle (6, 1.0); swim (8, 1.5) | the mob's block fluid is in tag `water` | if `gameTime < next`: `next = gameTime + 60`, return success without searching (read literally; the counter is pushed forward on every suppressed call). Otherwise search, then `next = gameTime + 60` | the first position, in Manhattan-scan order (radius), whose block differs horizontally from the mob's, has an empty fluid state, a collision-free block, and a block below whose top face is sturdy; completion range 1 |
| `TryFindLandNearLiquid(radius, speed, fluidTag)` | lay-spawn (8, 1.0, fluid tag `frog_tries_to_find_land_near`) | the mob's block fluid is **not** in the tag | same, with 40 ticks | the first position (differs horizontally, collision-free block, block below with a non-empty collision shape) that has a horizontal neighbour which is air and whose block below that neighbour has a fluid in the tag; completion range 0 |
| `TryFindLiquid(radius, speed, fluidTag)` | not used by the frog brain read here | the mob's block fluid is not in the tag | `next = gameTime + 20 + 2` on suppressed calls, +40 after a search | the first liquid block of the tag whose block above is air; failing that, the first liquid block of the tag at least 1.5 from the mob's position; completion range 0 |


### 1.3 Croak

`Croak` (frog only; needs `WALK_TARGET` absent; time-out 100): starts when the pose is STANDING; `start` does nothing if the frog is in a liquid, otherwise sets the pose CROAKING and the counter 0; continues while the counter < 60 (counter +1 per tick); `stop` sets the pose STANDING. The croak sound is played by the pose change handling of the frog class (not read).

### 1.4 Frog tongue (`ShootTongue`)

Constants: time-out 100, catch animation 6 ticks, tongue animation 10 ticks, unreachable-target memory cooldown 100 ticks, at most 5 unreachable targets remembered. Needs `WALK_TARGET` absent, `ATTACK_TARGET` present, `IS_PANICKING` absent. Start check: the target must be path-reachable (otherwise the target is erased and added to the unreachable memory) and the frog's pose is not CROAKING and `Frog.canEat(target)`. **`Frog.canEat(entity)`** (read): the test returns false for a cube mob (`AbstractCubeMob`) whose size is not 1; every other case, including a size-1 cube, falls through to the check that the entity is in entity type tag `frog_food`, whose members (data) are `slime` and `magma_cube`. So an entity other than a slime or magma cube is edible only if the tag lists it (it lists nothing else), and a cube is edible only at size 1. A size-1 cube cannot drop magma cream (section 10), so the magma cream case of the froglight table needs a cube of size 2 or more that was killed by something else. `start`: look at the target, set the tongue target, `WALK_TARGET` = target position with speed 2.0 and completion range 0 (read; the `TryFindLand` completion range 1 of section 1.2 is read too), state MOVE_TO_TARGET, path-recalculation counter 10. `stop`: erase `ATTACK_TARGET`, erase the tongue target, pose STANDING. Eating (`eatEntity`): plays the eat sound (neutral, volume 2, pitch 1); if the tongue target is alive the frog performs its melee `doHurtTarget` on it; if the target is still alive afterwards it is removed with reason KILLED. The state sequence is MOVE_TO_TARGET, CATCH_ANIMATION, EAT_ANIMATION, DONE. **`tick`** (read; constants `EATING_DISTANCE` 1.75 and `EATING_MOVEMENT_FACTOR` 0.75): each tick the tongue target is set to the current `ATTACK_TARGET`, then by state:

| State | Rule |
|---|---|
| MOVE_TO_TARGET | when the distance from the target to the frog is below 1.75: play the tongue sound (neutral, volume 2, pitch 1), set the frog's pose USING_TONGUE, set the **target's** motion to `normalise(target position to frog position vector) x 0.75` (it is pulled toward the frog), reset the animation timer to 0, state CATCH_ANIMATION. Otherwise, when the path counter is <= 0: set `WALK_TARGET` to the target's current position with speed 2.0 and completion range 0 and set the counter to 10; else decrement the counter |
| CATCH_ANIMATION | timer + 1 (the increment happens before the comparison); when the timer is >= 6 the state becomes EAT_ANIMATION and `eatEntity` runs |
| EAT_ANIMATION | when the timer is >= 10 the state becomes DONE; otherwise timer + 1 |

### 1.5 `MobSensor` (armadillo scare sensor)

`MobSensor(interval, mobTest, readyTest, memory, ttl)` requires `NEAREST_LIVING_ENTITIES`. Each sensing pass: if `readyTest(owner)` is false the memory is erased; otherwise, if any entity in `NEAREST_LIVING_ENTITIES` satisfies `mobTest(owner, entity)`, the memory is set true with expiry `ttl`. Registered as `armadillo_scare_detected`: interval 5, memory `DANGER_DETECTED_RECENTLY`, ttl 80; the two predicates are, in the order of the `SensorType` registration, the armadillo's `isScaredBy` (the two-argument test, `mobTest`) and then `canStayRolledUp` (the one-argument test, `readyTest`) (read).

## 2. Equines

### 2.1 Jump scale (answers 19 Open question 7)

`PlayerRideableJumping.getPlayerJumpPendingScale(p)` is read: for `p >= 90` the scale is **1.0** (read, not inferred); otherwise `0.4 + 0.4 x p / 90`. `onPlayerJump(p)` (saddled only): `p < 0` becomes 0 and does not make the horse stand; otherwise the horse may rear (`standIfPossible`, `allowStandSliding` true). The scale is stored as the pending scale. On the next ridden tick on the ground with a pending scale > 0 and not already jumping, `executeRidersJump` launches (formula in 19 section 3.1) and the pending scale resets to 0. Ridden rotation: pitch is half the rider's pitch, yaw equals the rider's; the body and head yaw follow.

### 2.2 Llama (answers 19 Open question 8)

**Caravan** (`LlamaFollowCaravanGoal(speed 2.1)`, flag MOVE; `CARAVAN_LIMIT` 8):

1. `canUse`: not leashed and not already in a caravan. Scan llamas and trader llamas in the box inflated (9, 4, 9) around the llama. First choice: the nearest llama that is in a caravan and has no tail. If none: the nearest leashed llama without a tail. Both choices only among those within the squared distance found so far. No candidate: false. Candidate closer than squared distance 4 (2 blocks): false. If the llama itself is not leashed, the candidate chain must reach a leashed llama within 8 hops (`firstIsLeashed`), else false. On success the llama joins: its head is the candidate and the candidate's tail is the llama.
2. `canContinueToUse`: in a caravan, the head alive, and the chain still reaches a leashed llama (hop limit 8). If the squared distance to the head exceeds 676 (26 blocks): when the speed is <= 3.0 the speed is multiplied by 1.2, the distance counter is set to 40 and the goal continues; otherwise it ends when the counter has reached 0. The counter counts down by 1 per tick otherwise.
3. `tick`: do nothing unless in a caravan or when leashed to a fence knot. Otherwise move toward the point `max(0, distance to head - 2)` blocks along the line from the llama toward the head, at the current speed.
4. `stop`: leave the caravan and reset the speed to 2.1.

**Targets.** `LlamaHurtByTarget` is the plain hurt-by goal (no ignored classes), except that `canContinueToUse` returns false once after the llama has spat (the `didSpit` flag is consumed). `LlamaAttackWolf` is a nearest-attackable goal for wolves with random interval 16, must-see false, must-reach true, accepting only wolves that are not tame; its follow distance is the base value x 0.25. The trader llama additions are in 19 section 3.7.

### 2.3 Camel and camel husk (answers 19 Open question 9)

**`RandomSitting(minimalPoseSeconds)`** is the idle entry `RandomSitting(20)`: the minimal pose time is `20 x 20 = 400` ticks. It starts when the camel is not in water, `poseTime >= 400` (`Camel.getPoseTime`: `poseTime = gameTime - |lastPoseChangeTick|`, the absolute value applies only to the stored tick, there is no outer absolute value), not leashed, on the ground, has no controlling passenger and `canCamelChangePose` (the target pose, SITTING when standing and STANDING when sitting, would not suffocate). `start`: if sitting, stand up; otherwise sit down unless panicking. The behaviour has no running state (empty memory requirements, default duration). It is one of the four weight-1 entries of the last idle `RunOne` (`RandomStroll(2.0)`, `SetWalkTargetFromLookTarget(2.0, 3)`, `RandomSitting(20)`, `DoNothing(30, 60)`; the first two are wrapped so that they need the walk target absent; see 19 section 3.8 for the gates). Temptation and baby-follow are a different `RunOne` at their own priority (next paragraph).

Camel brain constants read: core activity `Swim(0.8)`, `CamelPanic(4.0)` (starts only when the camel is not mob-controlled, and stands up instantly), `LookAtTargetSink(45, 90)`; idle: look at player within 6 every 30 to 60 ticks, `AnimalMakeLove(camel)`, then (priority 2) a `RunOne` of two weight-1 entries: `FollowTemptation(speedFn, closeEnoughFn)` and a baby-follow entry, then (priority 3) `RandomLookAround(U(150, 250), 30, 0, 0)`, then (priority 4) the four-entry `RunOne` listed above. Read: the `FollowTemptation` speed function returns 2.5 for everyone; its close-enough function returns 2.5 for a baby and 3.5 for an adult (the constants `DEFAULT_CLOSE_ENOUGH_DIST` 2.5 and `BACKED_UP_CLOSE_ENOUGH_DIST` 3.5 of `FollowTemptation`; the value is compared with `distanceToSqr`, so it is a squared-distance threshold as written, not a block distance). The baby-follow entry is `BabyFollowAdult.create(U(5, 16), 2.5)`: a constant speed 2.5 for every camel, range U(5, 16), gated by a negated predicate (its content was not read). Camel constants (read): dash cooldown 55 ticks, minimum dash duration 5, sit-down 40 ticks, stand-up 52, idle minimum 80, dash vertical momentum 1.4285, dash horizontal momentum 22.2222, running speed bonus 0.1, sitting height difference 1.43, baby scale 0.6. The camel husk food is rabbit foot (tag `camel_husk_food`), and its dash sounds `entity.camel_husk.dash` and `.dash_ready` exist, which supports the same-suffix claim of section 17. `standUpInstantly` (`resetLastPoseChangeTickToFullStand`) sets the last-change tick to `max(0, gameTime - 52 - 1)` so the stand-up animation counts as finished (read).

**Camel husk.** It extends the camel: removed when far away (`removeWhenFarAway` true), `isMobControlled` when its first passenger is a mob, interacting sets persistence required, can be leashed only when not mob-controlled, food tag `camel_husk_food`, never mates and never a baby (`canMate`, `canFallInLove`, `canBeABaby` false, no offspring), charge speed modifier 4.0, and its own sounds (section 17). The jockey (a parched riding a husk-spawned camel husk) is spawned by the husk, not by the camel husk: see 20 section 4.3.

## 3. Rabbit jump control (answers 19 Open question 10)

The rabbit uses its own jump control and move control.

- **Jump control**: `wantJump` returns the base `jump` flag; `canJump` is a flag set by `enableJumpControl`/`disableJumpControl`; each tick, if the flag is set the rabbit's `startJumping` runs (sets jumping, jump duration 15, jump ticks 0) and the flag clears.
- **Move control**: each tick, if the rabbit is on the ground, not jumping and the jump control does not want a jump, the speed modifier is set to 0 (stop). If the control has a wanted position or its operation is JUMPING, the speed modifier is set to the remembered `nextJumpSpeed`; then the base move tick runs. `setWantedPosition(x, y, z, speed)`: when in water the speed is forced to 1.5; the remembered speed is updated when the speed > 0.
- **Server tick** (`customServerAiStep`): `jumpDelayTicks` and `moreCarrotTicks` count down (the latter by `nextInt(3)`, floor 0). When on the ground: if it was not on the ground last tick, jumping is cleared and `checkLandingDelay` runs (sets the delay to 10 when the move speed modifier is below 2.2, else 3, and disables the jump control). An evil (killer) rabbit with `jumpDelayTicks == 0` and a target within squared distance 16 faces the target, sets the move target to it and jumps immediately. Otherwise, when the jump control does not want a jump, the move control has a wanted position and `jumpDelayTicks == 0`: face the next path node (or the wanted point if there is no path) and start the jump. When the jump control cannot jump, it is enabled again.
- `facePoint(x, z)`: yaw = `atan2(z - Z, x - X)` in degrees minus 90.
- Jump power and the post-jump push are in 19 section 4 (`getJumpPower`: 0.3, 0.2 for speed <= 0.6, 0.5 when the next node is above or the wanted y is above; passed through the shared `getJumpPower(p / 0.42)`); `jumpFromGround` adds a horizontal nudge of 0.1 x (0, 1.5 or 0.5 for a baby, 1) in the facing direction when the speed modifier > 0 and the horizontal motion squared is under 0.01, and broadcasts entity event 1.

## 4. Fox (answers 19 Open question 11)

Shared constants: `canEat(item)` = the item has the food and consumable components, the fox has no target, is on the ground and not sleeping. Eating (`aiStep`, effective AI): `ticksSinceEaten` increments; when the main hand holds an edible item: after 600 ticks the fox finishes using it (the result stays in hand if non-empty) and the counter resets; from tick 560, 10 percent per tick plays the eating sound; a particle event 45 is broadcast. A fox with a target that is alive keeps its crouch state; otherwise crouching and interested flags clear. When sleeping or immobile (dead) the movement input is zeroed.

- **Pick-up** (`canHoldItem`): when the hand is empty, or the hand is edible-after-timeout and the new item is not edible; `pickUpItem` takes one item (the rest of the stack is dropped), spits out what was in hand, marks the main-hand drop guaranteed, resets `ticksSinceEaten`. `ALLOWED_ITEMS` accepts item entities without a pick-up delay that are alive. Item search (`FoxSearchForItemsGoal`, MOVE): usable with an empty hand, no target and no last-hurt-by, able to move, a 1 in `reducedTickDelay(10)` roll, and an allowed item entity within the box inflated 8 in each axis; it moves to the first listed item at speed 1.2.
- **Targets by variant** (`setTargetGoals`): red variant: priorities 4 land prey, 4 turtle-egg hunter, 6 fish hunter; other variants: 4 fish, 6 land prey, 6 turtle eggs. The land-prey goal is a nearest-attackable goal on `Animal` (interval 10) whose selector accepts only a chicken or a rabbit; the fish goal is on `AbstractFish` (interval 20) with a selector accepting only schooling fish; the turtle goal uses the baby-turtle-on-land selector (the 19 section 7 table has the full list). No condition about defending was found in these goals.
- **Trust**: `trusts(entity)` is membership in the trusted list (entity references). `addTrustedEntity` is called by `FoxBreedGoal.breed` for the love causes of both parents (each a player) after the baby is created; the parents' age is set to 6000 and love reset, the baby's age to -24000. Nothing else was found that adds trust (the saved list is stored with the fox). Untrusted selectors: `TRUSTED_TARGET_SELECTOR` accepts a living entity whose last-hurt-mob timestamp is within 600 ticks (it recently attacked); `AVOID_PLAYERS` accepts a non-crouching (`isDiscrete` false) player that is not creative or spectator. A fox flees from an untrusted such player unless it is defending.
- **`DefendTrustedTargetGoal`** (nearest-attackable with random interval 10): picks, each interval, the first trusted entity (resolved to an entity); its last-hurt-by attacker, if newer than the stored timestamp and attackable by the target conditions, becomes the target. `start`: set the target, store the timestamp, play the aggro sound, set defending, wake up. While defending, `aiStep` plays the aggro sound with probability 0.05 per tick.
- **`StalkPreyGoal`** (MOVE, LOOK): not sleeping, target alive and in `STALKABLE_PREY` (chicken or rabbit), squared distance > 36, not crouching, not interested and the fox's own flag test passes. `tick`: look at the target; when within squared distance 36, set interested and crouching and stop navigation. `stop`: if the path to the target is clear (`isPathClear`: six sample steps along the line, four vertical samples each, all must be passable), set interested and crouching, stop navigation and look at the target; otherwise clear both.
- **`FoxPounceGoal`** (not interruptable): needs a fully crouched fox, a living target, the target's motion direction equal to its facing direction, and a clear path (otherwise it clears crouching and interested and fails). ## 19. Worked examples

1. **Long jump vector.** Frog at P = (0, 64, 0), target block (4, 64, 0) so T = (4.5, 64.5, 0.5). The horizontal part of `T - P` is `(4.5, 0, 0.5)`, of length 4.5277 (the y difference 0.5 is applied separately below), and `d = (4.5, 0, 0.5) / 4.5277 x 0.5` is about (0.4969, 0, 0.0552); `T' = (4.0031, 64.5, 0.4448)`; `r = (4.0031, 0.5, 0.4448)`. With angle 65 degrees: `A = 16.2226`, `H = 4.0277`, `sin 130 = 0.7660`, `cos^2 65 = 0.1786`, `g` is the gravity attribute default 0.08 (read; the frog does not override it): the denominator is `4.0277 x 0.7660 - 2 x 0.5 x 0.1786 = 3.0854 - 0.1786 = 2.9068`, `v^2 = 16.2226 x 0.08 / 2.9068 = 0.4465`, `v = 0.668`. This must not exceed `jump_strength x 3.5714288`: the frog sets no jump strength (3.5714288 is the constant `MAX_JUMP_VELOCITY_MULTIPLIER` in the frog AI class, not a registered goal parameter. (`Frog.createAttributes` sets movement speed 1.0, max health 10, attack damage 10, step height 1.0 over the animal base)), so the generic attribute default 0.41999998688697815 applies (not a frog value) and the limit is 0.42 x 3.5714 = about 1.5; v = 0.668 passes. The launch vector is `0.95 x v` split by the angle.
2. **Llama strength.** Parents of strength 3 and 5: `nextInt(5) + 1` is 1 to 5; with the 3 percent bonus the value can reach 6, clamped to 5 by the setter. Chested slots for a strength-4 llama: `3 x 4 = 12`.
3. **Sniffer egg timing.** On a moss block: stage delay `12000 / 3 + nextInt(300)` = 4000 to 4299 ticks per stage, three stages (placed 0, 1, 2; hatches on the tick with `hatch == 2`), so 12000 to 12897 ticks total (about 10 minutes); on other blocks 8000 to 8299 per stage.
4. **Armadillo scare.** A sprinting player at 6 blocks horizontally and 1 block vertically is inside the inflated box (7, 2, 7): `DANGER_DETECTED_RECENTLY` is set for 80 ticks; the armadillo rolls up (state ROLLING), after 11 ticks is SCARED; while the danger memory has more than 75 ticks left the peek timer is `50 + U(100, 400)`.
5. **Wolf teleport.** Owner at block (100, 64, 100), the wolf 15 blocks away (squared 225 > 144): attempt 1 draws `dx = 1, dz = 0`: both below 2, skip; attempt 2 draws `dx = -3, dz = 2, dy = 0`: the block (97, 64, 102) must be WALKABLE, the block below not leaves, and the box collision-free; then the wolf snaps to (97.5, 64, 102.5).
6. **Goat horn.** Goat moving horizontally in direction (1, 0, 0) at (10.5, 65, 5.5): the tested blocks are those at (11.5, 65, 5.5) and one above; an oak log at (11, 65, 5) breaks the horn (the tag covers `#overworld_natural_logs`).
7. **Parrot.** 1 in 400 per tick imitation chance x 1/2 gate: expected one imitation every 800 ticks (40 s) when a non-parrot, non-silent mob is within 20 blocks.

## 20. Validation checklist
